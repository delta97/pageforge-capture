# PageForge Capture — Toolbar Popup UI

## Context

Today, clicking the toolbar icon fires `chrome.action.onClicked` in `background.js`, which directly calls the capture pipeline (`captureFullPage(tab)`) — there's no intermediate UI. The user wants a small popup (in the spirit of the "inspiration extension," e.g. GoFullPage) that opens on icon click and gives a menu: **Capture** or **Settings** — plus a reserved spot for future **dev tools**.

Two design decisions were confirmed with the user up front, since Chrome's `default_popup` behavior forces them:
- **Once a popup is set, `chrome.action.onClicked` never fires again, and the existing `Alt+Shift+P` shortcut (`commands._execute_action`) always opens the popup too** — it can no longer instant-capture. This is accepted as intended new behavior; no secondary "instant capture" shortcut is being added.
- The "dev tools" ask is a **placeholder only** for now — a clearly-labeled, non-interactive "Developer — coming soon" section, not real functionality.

This is purely additive: `content.js`, `result.*`, and `options.*` are untouched. The only behavior change to existing code is swapping the dispatch entrypoint in `background.js` from `onClicked` to a message listener.

## Approach

### 1. `manifest.json`
Add `"default_popup": "popup.html"` to the `action` block:
```json
"action": {
  "default_title": "Capture full page",
  "default_popup": "popup.html"
}
```
No permission changes — `activeTab` already covers reading `tab.url` when the popup opens (opening the popup is itself the qualifying user gesture that grants it), so `chrome.tabs.query` in `popup.js` works without adding `tabs` or `host_permissions`.

### 2. `background.js` — swap `onClicked` for a message listener
Remove the now-permanently-unreachable block:
```js
chrome.action.onClicked.addListener((tab) => { ... });
```
Replace with a `chrome.runtime.onMessage` listener that the popup calls into, preserving 100% of the existing `captureFullPage` pipeline (session creation, badge updates, error handling via `showErrorResult`) unchanged:
```js
chrome.runtime.onMessage.addListener((message, _sender, sendResponse) => {
  if (message?.type !== 'PFC_TRIGGER_CAPTURE') return;

  (async () => {
    try {
      const tab = await chrome.tabs.get(message.tabId);
      if (!tab?.id || !tab?.windowId) {
        sendResponse({ ok: false, error: 'No active tab found to capture.' });
        return;
      }
      sendResponse({ ok: true });
      captureFullPage(tab).catch(async (error) => {
        console.error('PageForge capture failed', error);
        await showErrorResult(error?.message || String(error));
      });
    } catch (error) {
      sendResponse({ ok: false, error: error?.message || String(error) });
    }
  })();

  return true; // keep the channel open for the async sendResponse above
});
```
`sendResponse({ ok: true })` fires right after tab resolution — *before* `captureFullPage` resolves — so the popup can close immediately without waiting on the multi-second capture loop. This also structurally prevents double-capture from rapid double-clicks: the popup disables its button and closes on click, so a second trigger requires reopening the popup and re-running its tab query.

### 3. New file `popup.html`
Small popup (~320px wide, auto height), reusing `result.html`'s `.brand`/`.brand-mark` header pattern at popup scale:
- Header: "PF" mark + "PageForge Capture" title/subtitle.
- `<button id="captureBtn" class="button primary full" disabled>Capture full page</button>` + a hidden `<p id="captureNote">` for disabled-state explanations.
- `<button id="settingsBtn" class="button secondary full">Settings</button>`.
- A static, non-interactive `.dev-section` with a dashed border and "Developer — coming soon" label — no click handler, no button element, so it can't be mistaken for a broken control.

### 4. New file `popup.css`
Reuse `result.css`'s `:root` custom-property token set verbatim (`--bg`, `--panel`, `--text`, `--muted`, `--line`, `--primary`, `--primary-dark`, `--danger-*`) rather than `options.css`'s hardcoded hex values, plus the same `.button`/`.button.primary`/`.button.secondary`/`:disabled` classes — this keeps the popup visually consistent with the rest of the extension and gets hover/disabled states for free. Add popup-specific layout: `body { width: 320px; }`, compact `.brand` header, `.content` flex column, `.dev-section` dashed-box styling.

### 5. New file `popup.js`
The only genuinely new logic — a capturability check that doesn't exist anywhere else in the codebase today:
```js
const UNSUPPORTED_SCHEMES = ['chrome:', 'chrome-extension:', 'edge:', 'about:'];
const CHROME_WEB_STORE_HOSTS = ['chromewebstore.google.com', 'chrome.google.com'];

function getCaptureBlockReason(url) {
  if (!url) return 'This tab cannot be captured.';
  let parsed;
  try { parsed = new URL(url); } catch { return 'This tab cannot be captured.'; }
  if (UNSUPPORTED_SCHEMES.includes(parsed.protocol)) return 'Chrome blocks extensions from capturing internal browser pages.';
  if (CHROME_WEB_STORE_HOSTS.includes(parsed.hostname)) return 'Chrome blocks extensions from capturing the Chrome Web Store.';
  return null;
}
```
On load: `chrome.tabs.query({active:true, currentWindow:true})` to get the current tab (first use of this exact pattern in the codebase — `background.js` only ever had a tab handed to it directly). If no tab, or `getCaptureBlockReason` returns a message, disable the Capture button and show the note. Otherwise wire up the click handler.

Capture click handler sends the message and closes on the **callback** (not the Promise form, and not immediately after calling `sendMessage`) — waiting for `sendResponse` to round-trip before `window.close()` avoids a real reliability gotcha where closing the popup immediately after an un-acknowledged `sendMessage` can tear down its JS context before the IPC dispatch completes:
```js
function triggerCapture(tabId) {
  els.captureBtn.disabled = true;
  chrome.runtime.sendMessage({ type: 'PFC_TRIGGER_CAPTURE', tabId }, () => {
    void chrome.runtime.lastError;
    window.close();
  });
}
```
Settings button: `chrome.runtime.openOptionsPage(); window.close();`.

### Files touched
- `manifest.json` — add `default_popup`
- `background.js` — replace `onClicked` listener with `onMessage` listener (capture pipeline itself unchanged)
- `popup.html`, `popup.css`, `popup.js` — new
- Not touched: `content.js`, `result.*`, `options.*`, `icons/` (existing icon sizes are sufficient)

### Edge cases handled
- No active tab found → button disabled with explanatory note, no crash.
- Empty/malformed `tab.url` → guarded before `new URL()`, falls back to a generic message.
- Tab closes in the gap between popup query and background's `chrome.tabs.get` → caught, popup has already closed, no-worse-than-today.
- Rapid double-invocation → prevented structurally (button disables + popup closes on first click).

## Verification

1. `chrome://extensions` → reload unpacked → confirm no manifest errors.
2. Click the toolbar icon on an `https://` page → popup shows enabled Capture, Settings, and a static "Developer — coming soon" box.
3. Click Capture → popup closes immediately, badge shows progress, a new `result.html` tab opens with the finished capture (regression check against existing pipeline).
4. Click Settings from the popup → options page opens, popup closes.
5. Open the popup on a `chrome://` page → Capture button disabled with the internal-page message.
6. Open the popup on the Chrome Web Store → Capture button disabled with the Web Store-specific message.
7. Press `Alt+Shift+P` on an ordinary page → same popup opens (not an instant capture).
8. Check the service worker console (`chrome://extensions` → "service worker") for errors while doing the above, including triggering a capture on a page where script injection fails, to confirm `showErrorResult` still fires via the new message path.
9. Confirm `chrome.action.onClicked` is fully removed with no stale references.
